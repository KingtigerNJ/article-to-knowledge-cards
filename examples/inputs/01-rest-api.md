# 什么是 REST API

REST 是一种用于设计网络接口的架构风格，全称是 Representational State Transfer（表述性状态转移），由 Roy Fielding 在 2000 年的博士论文中提出。

REST 的核心思想是：把服务器上的每样东西都看作一种"资源"，并用统一的 URL 来标识它。客户端通过 HTTP 方法来对资源进行操作，而这些方法本身带有语义：GET 用于读取资源，POST 用于创建资源，PUT 用于整体替换资源，PATCH 用于部分更新资源，DELETE 用于删除资源。

REST 强调"无状态"：服务器不保存两次请求之间的客户端状态，每个请求都必须自带完成它所需的全部信息。这样做的好处是服务器更容易横向扩展——任意一台服务器都能处理任意一个请求。

REST 还要求接口是"面向资源"而不是"面向动作"的。比如要删除 ID 为 5 的用户，好的设计是 `DELETE /users/5`，而不是 `GET /deleteUser?id=5`。前者把动作编码进了 HTTP 方法，后者则把动作塞进了 URL。

需要说明的是，REST 是一种风格而不是强制标准，因此现实中很多号称 REST 的接口其实只做到了部分原则。真正严格的 REST 还要求使用 HATEOAS，即响应中携带指向后续可用操作的链接，但这一点在实践里很少被实现。

REST 常被拿来和 RPC 风格对比。RPC 关注"调用某个函数"，而 REST 关注"对某个资源做什么操作"。这也是为什么 REST 接口通常围绕名词（资源）来组织 URL。
